Three tools, one engine

Decompiler

Bytecode back to Java

Reads the constant pool, the fields, the methods and the code, and emits Java. Methods that do not branch come out directly. Methods that do are lowered to a state machine, and the app tells you the split instead of pretending.

Obfuscator

Protect a jar you own

Rename members, encrypt the string table, flatten control flow and strip debug info, one pass at a time so you can see what each one costs you at startup.

Deobfuscator

Undo that protection

Apply mappings, recover the string table by running the decryptor in isolation, unfold the dispatcher and fold dynamic constants back into literals.

The report

What the archive is hiding

A 0 to 100 score built from weighted signals, and findings that name the class and method they came from: a decryptor that reads the call stack, a wide switch dispatcher, a native load, a cipher, high entropy constants.

The score is calibrated against real jars and the calibration is a test, so it cannot quietly stop meaning anything.

It parses. It never runs.

A jar is a hostile file. You do not know what is inside it, and the whole point is that it may be trying to do something to the machine you run it on.

binpeek treats it that way. Every read is bounds checked, a lying or truncated file is refused rather than guessed at, all work happens in a worker with hard limits on entries, inflated bytes, compression ratio, classes, strings and time, and the report prints the caps that were in force.

Straight answers

Do I need Java installed?

No. The app is a single self contained file. It needs Windows and the WebView2 runtime, which is already part of Windows 11 and of any current Windows 10.

Is it legal to use on a jar that is not mine?

The tools are for code you own or are allowed to modify. Deobfuscating something you did not write, or that you are not authorised to change, is on you.

How is the download gated?

A payment through Stripe mints a signed, expiring token with a download count attached, and that token is what unlocks the file. There is no account database to compromise, which is also why there is no password to leak.

How good is the decompiler really?

On a real Fabric mod it fully understands about 85 percent of methods and emits about 65 percent as straight line Java. On heavily obfuscated jars it drops to roughly 75 percent understood. The app shows you the numbers for your file rather than a claim.
